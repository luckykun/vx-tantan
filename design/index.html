01需求确认结论

本文档描述 v2 玩法（变更决策记录见 specs/design-v2-changes.md）。v1 的回合制 / 9 列网格 / 剩余次数评星 / 瞄准虚线等设定已被整体取代，涉及处均已改写。

原始需求经 v1 确认 + v2 复述，最终结论如下（后续所有设计均以此为准）：

议题确认结论设计影响
横条行为 横条是挡板，需要接球（非纯发射器） 横条具备双重身份：既是发射点，又是回弹工具。拖空白处瞄准 / 发射，拖横条本身摆位；球落回时接住即沿拖动方向弹回去继续消除。
接住回弹
v2 改		 挡板接住球后不回收成弹药，而是按当时拖动方向继续回弹，球持续消除；球漏完且弹药耗尽才结束 删除 v1「接住转弹药 / 回合结算」整套机制。回弹注入横向分量 vx += paddle.vx × BOUNCE_KICK(0.55)，静止接住则近似原路竖直回弹。「控住拖动方向」成为核心手感。
方块数量
v2 改		 网格改 30 列（原 9 列），方块要很多才有意思；不加血量，保留分裂道具方块 方块总数从 v1 的 26/37/49 提升到 101/167/212（全高度散布）。普通方块命中 1 次即消除；难度靠「3 次发射 + 缺口造型 + 停滞开底」，不靠血量堆叠。
关卡模式
v2 改		 关卡制 + 每关 3 颗球发射机会 + 按耗时评星 发射第 1 颗后可立即发下一颗（允许同屏多波）。星级按通关耗时评定（废弃 v1「剩余次数比例」评星）；天然适配关卡解锁、星级收集与分享裂变。
需求原文的一处歧义与本文的处理 「横条处于水平居中」理解为横条水平放置且位于屏幕底部居中位置（而非“横条在水平方向上可居中移动”）。 瞄准时横条不跟随手指 X（否则「横条中心 → 手指」的连线会永远竖直、无法斜射）， 因此保留双模式手势：拖空白处 = 瞄准/发射，拖横条本身 = 摆位/接管回弹（详见 06 交互手势）。

02产品定位与核心体验

一句话定位

「算好角度，一杆清台」——
用手指弹射小球，在封闭容器里打出连锁反弹的爽快感。

品类：休闲益智 / 弹射消除。对标：Bricks n Balls、弹球消砖块、Ballz。 差异化：封闭容器 + 单一缺口——球必须"钻进去"，进去后在密闭空间里疯狂反弹， 比开放式的打砖块更有"台球 / 弹珠台"的策略感与观赏性。

三层体验目标

思考弹道预测线让"算角度"变成可视化推理，而非瞎猜
操作接球环节提供动作紧张感，把"策略游戏"拉回"手感游戏"
爆发分裂块让球数指数增长，满屏弹球 + 连击飘字 = 核心爽点

目标用户与场景

  • 主力人群：18~40 岁微信休闲用户，女性占比预计偏高（消除类品类特征）。
  • 使用场景：碎片时间（通勤、排队、睡前），单局 54~123 秒（v2 连续回弹制，胜局仿真实测），随时可中断续玩。
  • 留存钩子：关卡星级收集 → 每日挑战关 → 好友排行榜 → 卡关时"看广告 +1 颗球"。

03核心玩法闭环

摆位
拖横条选择发射点→ 瞄准
弹道预测点列→ 发射
扣 1 颗球→ 穿缺口入容器→ 反弹消除
命中即消除→ 触发分裂
1 球 → 2 球→ 从缺口逸出→ 接住回弹
拖横条接住，沿拖动方向弹回↺ 球漏完且弹药耗尽 → 结算

① 连续回弹链

开局发 1 球 → 击中分裂块变 2 球 → 球从缺口逸出后拖横条接住并沿拖动方向弹回， 球不因接住而消失，而是继续消除。一条“接住→回弹→再消除→再逸出→再接住”的回弹链 可以把一颗球的火力放到最大，把「策略锁定」与「动作回弹」接成一个大动作流。

② 失败压力与收敛

失败由3 颗球全部漏完且发射机会耗尽触发。两道收敛保险： 连续 22s 无消除自动开底排空活球；关卡硬超时 240s强制开底。 保证无重力封闭容器里不会出现“球永远绕不出来”的死锁。

③ 单局节奏

v2 将“每关 3 球 + 回弹链”作为节奏引擎：球全程有块可打（散布布局）， 胜局均耗时 54~123s（仿真实测）；三星线取熟练中位、二星线取新手中位。 飞行期间玩家不闲着（要拖横条接住回弹），有明显空窗。

胜利 / 失败条件

结果触发条件后续流程
通关场上所有可消除方块（含分裂块）清空（即时判定，不等球落完）结算页：耗时星级 + 得分 + 消除数/最长回弹链 → 「下一关」/「重玩」/「分享炫耀」
失败3 次发射机会用完 且 同屏球全部漏完，方块仍有剩余失败页：显示剩余方块数 → 「重新挑战」/「看广告 +1 球」/「返回选关」
中断暂停 / 切后台（onHide）自动暂停主循环并保存当前局面，回前台可继续（防切屏作弊：暂停期间不计入单局时长）

为什么缺口逐关递增收窄而不统一关键决策

球必须穿过缺口才能进入容器，因此可瞄准角度存在硬性容差上限。v2 采用逐关递增收窄（前宽后窄）： 

入射容差角 = atan( (缺口宽 ÷ 2 − 球半径 − 1) ÷ 发射点到缺口上沿距离 256.1px )

L1 缺口 12 格（140.4px）：atan((70.2 − 5.5 − 1) ÷ 256.1) = ±14.0°  → 新手宽缺口，易上手
L2 缺口 10 格（117.0px）：atan((58.5 − 5.5 − 1) ÷ 256.1) = ±11.5°  → 需主动摆位
L3 缺口 8 格（93.6px）： atan((46.8 − 5.5 − 1) ÷ 256.1) = ±8.9°   → 窄口，重心靠回弹链

（v1 统一 3 格（117px）但格宽 39 → 容差 ±22.2°；v2 格宽变小使相同格数的绝对宽度变小）
配套设计：把"限制"变成"玩法" 弹道预测点列用颜色实时反馈本次发射能否命中可消块—— 青色 = 可命中， 红色 + ✕ 标记 = 无命中（慎发）。 需求方 v2 拍板去掉“挡板中心→手指”的方向虚线，只保留一条真实弹道预测点列（见 06）。同时接球区保留左右外壁，允许"打库边"折射入缺口。

06交互手势设计

全程单指操作，无按钮依赖。v2 把瞄准/发射/回弹/接球合并到单一 PLAY 态内并行（球飞行时也可随时拉下一条瞄准线并发射下一颗）。核心矛盾仍是横条既要当"发射基准"又要当"回弹工具"，解法还是按触摸落点区分双模式（不再依赖 AIM/FLY 互斥阶段）：

瞄准辅助反馈（降低挫败感的关键）

  • 弹道预测点列：与真实物理同一套规则步进模拟；渐隐点列 + 首个命中方块处画双圆圈。v2 已删除“挡板中心→手指”的流动虚线（需求方拍板“只应有一条线”），只剩这一条真实弹道预测。
  • 颜色反馈：青色=可命中可消块，红色 + ✕=无命中（慎发）。
  • 角度读数：挡板下方显示 +18° 与文案「可命中」/「无命中(慎发)」。
  • 失败预标记：预测无命中时，在撞击点画红色 ✕。
  • 手指锚点：手指位置画双环，明确"我在控制这里"。

手感细节

  • 热区扩展：横条实际高 12px，触摸热区向上下左右扩展（移动端最小可点击 44px 规范）。
  • 抓取偏移：摆位模式记录 grabDX = 手指x − 横条中心x，避免横条瞬间跳到手指下方。
  • 接管无偏移：无弹药时紧急情况要"指哪到哪"，此时跳变可接受且必要。
  • 插值跟随：横条用 dt×22 插值，视觉顺滑；其拖动速度就是接住回弹时注入的横向分量来源。
  • 误触保护：摆位模式下松手不发射，玩家可反复调整后再去空白处瞄准。
  • 角度限制：与竖直方向夹角 ≤ 78°，防止近乎水平的无效发射。

08物理与规则细则

8.1 双区物理模型核心决策

竞技区（容器内）

  • 无重力，小球匀速直线运动，速度恒定 500 px/s
  • 碰撞按完美镜面反射：v' = v − 2(v·n)n，恢复系数 = 1（无能量损失）
  • 碰撞对象：容器左/右/顶壁、墙壁方块、可消除方块
  • 意义：弹道 100% 可预测，预测线即真实轨迹，"算角度"成立

接球区（缺口以下）

  • 无重力，匀速直线（保持全场景物理统一，无需抛物线预测）
  • 速度 ×0.84 → 420 px/s，给玩家反应时间（v7 需求④）
  • 左右保留容器外壁（可打库边反弹），球不会白白飞出屏幕
  • 接住→沿拖动方向回弹（v2）；球心越过漏接线→该球永久消失
为什么不用重力？ ① 需求描述是"按角度反弹"，属镜面反射语义；② 无重力时弹道是直线，预测线绘制简单且与真实轨迹完全一致， 这是"算角度"类玩法的信任基础；③ 有重力则弹道为抛物线，容器内球会很快坠向缺口，回合过短、策略性差。 备选方案（若后续想要更"物理感"）：仅接球区施加重力 g = 800 px/s²， 竞技区仍无重力——落点更自然，但接球预测需改抛物线，且要重新配平横条宽度。

8.2 碰撞检测与防穿透

技术点方案原因
子步进每帧将 dt 切成 8 份依次推进并检测60fps 下 500px/s 每帧移动 ~8.3px；格宽仅 11.7px，单帧检测必穿透，8 子步进后单步 ~1.04px < 球径，即使 900px/s 也不穿透（已压测）
圆 vs AABB取矩形上距球心最近点，判定距离 < 半径标准做法，法线即"最近点→球心"方向，天然正确
广相裁剪只检查球 AABB 覆盖的网格单元（最多 2×2 = 4 格）O(1) 复杂度，与方块总数无关，16 球 × 8 子步进 × 4 格 = 512 次检测/帧，性能无压力
多碰撞取舍同一子步进内只解算穿透最深的一个碰撞避免同时解算多个碰撞导致的抖动 / 弹飞
陷入处理球心已在方块内部时，按最小穿透轴确定法线并整体推出此时最近点 = 球心，法线无定义，必须特殊处理，否则球会卡死在方块里
位置修正推出距离 = r − d + 0.2（额外 0.2px 余量）防止浮点误差导致同一碰撞被连续触发
速度归一每次反弹后重新归一化到目标速度累积浮点误差会让球速漂移，长时间回合后可感知
反退化速度分量下限 = 9% × 速率，不足则抬升并重新归一避免完全水平 / 完全垂直的弹道在矩形容器内无限循环，永不落地

8.3 分裂规则

触发：球击中「分裂道具方块 S」→ 方块消除 → 该球分裂为 2 颗
新球方向：原方向绕命中点旋转 ±20°（SPLIT_ANGLE；符号按当前球数奇偶交替，避免全部偏向同一侧）
新球位置：与母球重合后沿自身反方向回撤 0.012s（≈ 5px），避免母子球重叠导致二次碰撞
继承属性：速度大小、所在区域（arena / catch）
限制：① 同屏球数上限 16 颗，超出时只消除方块不分裂，并飘字"已达上限"
      ② 同一颗球分裂冷却 0.12s，防止在密集分裂块区域瞬间指数爆炸
      ③ 新球立即进入冷却（splitAt = now），避免"分裂出的球马上再分裂"
      ④ v2 地图每关分裂块限 0~2 个，因为回弹链已能提供持续火力，无需靠分裂指数爆炸
v2 分裂数量的控制 理论上 1 → 2 → 4 → 8 → 16 只需 4 次分裂。但 v2 每关只放 0~2 个分裂块（L1 零、L2/L3 少量）， 因为"3 球 + 接住回弹链"本身已把一颗球的价值放大很多，再叠加密集分裂会使同屏球数与清屏速度失控。 上限 16 是性能保险而非玩法常量：16 颗球 + 拖尾（每球 8 段）= 144 次圆形绘制/帧，中端安卓机可稳 60fps。若偏低端可降到 12 或关拖尾。

8.4 停滞开底与关卡硬超时v2 收敛机制

容器封闭 + 无重力 + 接住回弹 → 存在球永远在容器内回弹但不再产生消除的可能。 v2 取消回合计时，改用两道以“消除”为锚点的收敛保险：

  • 停滞计时 22s（STALL_TIME）：从上一次发生消除起计时；一旦发生新消除（destroyCell）立即归零。连续 22s 无任何消除→开底。
  • 剩余 3s 警告（OPEN_WARN）：底部墙壁行整体闪烁（透明度 0.72~1.0 正弦脉动），提示"要开底了"。
  • 关卡硬超时 240s（LEVEL_TIMEOUT）：elapsed ≥ 240s 无条件下令开底。防止“完美回弹链使球永不着地、但每次相邻消除间隔又永远 < 22s”导致停滞计时无法收敛（仿真实测撞到过）。
  • 开底行为：底部墙壁行 opened = true，失去碰撞体并淡出至 16% 透明度，所有球自由回落；开底期间接住不再回弹（保证必然收敛，也是对磨洋工的惩罚）。
  • 恢复封闭：若开底后又发生新消除（回写 stallTime 并重新封闭）；或球漏完且仍有弹药→回常闭 PLAY。
为何不用单一停滞计时，还要硬超时？ v2 仿真发现一个典型死局：残局只剩 1 个不可消方块（墙），完美回弹链使球永不着地（balls 恒 >0）， 上一颗可消块被消后 stallTime 归零，但后续再无新消除→ stallTime 持续累积；若残局单球大场地往返， 相邻两次消除的间隔可永远 < 22s，停滞计时无法单独收敛。因此额外加一条 240s 硬超时兜底（已写进代码与 §13）。

8.5 接住回弹

事件判定结果
接住回弹球与横条矩形（圆-矩形最近点法）相交球不消失，沿拖动方向弹回竞技区：vx += paddle.vx × BOUNCE_KICK(0.55)，钳制 ±78°；静止接住≈原路竖直回弹；+5 分；金色粒子 + 音效 + 轻震
漏接球心 y > 漏接线(652)球永久消失；连击清零；红色粒子 + 低沉音效 + 震动；若弹药已尽且无残留球→判负
胜负即时判定（无“回合结算”）任一可消块被清空→WIN；shotsLeft=0 且 balls.length=0 且仍有可消块→LOSE
v2 为何删掉"保底补 1 球"？ v1 需要保底是因为“接住转弹药”，漏接会导致下一轮无球可发的死锁。v2 中接住不回收入弹药，而是直接回弹， 弹药（3 颗发射机会）与同屏球是两个独立概念：只要还能发射，球总会落下；漏接的代价是“该球永久消失、火力减弱”， 而不会出现“有次数无球”的死锁，因此无需保底。“接住→回弹→再消除”本身就是正反馈。

11.1 测试工具自己先被证伪：4 处缺陷方法论

第一版脚本给出的结论是「三关全部达标」，但这个结论是错的。在把它当门禁固化之前逐条复核，发现工具本身有 4 处问题：

缺陷症状修复
① 结果不可复现同一份关卡数据、同样参数跑两次，通关率 88% 与 91% —— 门禁时过时不过，等于没有门禁 用 mulberry32 固定种子覆盖 Math.random（同时作用于玩家模型与游戏内部随机）。验证：同配置两次输出的文本用 fc 逐字节比对，差异 0
② 玩家模型是完美接球机器漏接率恒为 0.0%，接球环节完全没被验证；而 §15.2 的目标是 20%~35% 加两项人类约束：反应粒度 REACT = 60×(0.12+0.15×(1−skill)) 帧（新手 16 帧才改一次落点预判）、落点误差 ERR = 1.6×CELL×(1−skill) px（新手 ±19px）。原模型每帧重写落点且零误差，那不是人在玩
③ 统计口径丢数据漏接计数只在 caughtThisRound 变小时结算，某回合「接 0 漏 1」时该回合数据整批丢弃 → 报出误导性的 0.0% 改用两个计数的历史最大值，并以「双计数同时归零」作为回合边界来 flush
④ 异常计数串扰压测行打印的是全局 anomalies，「压测异常 1 项」实际是关卡平衡性的越界，容易让人误以为物理层有问题 压测前后取快照做差，两类异常分开计数
修完 ② 之后，之前「达标」的结论全部作废 加入人类约束后，三关的通关率整体下移 5~16pp（例如第 2 关新手档从 78.5% 掉到 61.9%，且跨种子极差高达 14pp）。 这说明仿真脚本的可信度必须先于它给出的数字被验证：一个失真但跑得通的测试，比没有测试更危险， 因为它会让「数值已配平」这个结论带着假信心进入开发排期。

13技术方案

13.1 形态选型：微信小游戏 vs 小程序内嵌 Canvas

维度微信小游戏（推荐）小程序页面内 canvas type=2d
运行环境无 DOM / window，专为游戏优化，冷启动更快带完整小程序运行时，页面层仍是 WebView
性能纯 Canvas，无排版开销，帧率稳定Canvas 与 DOM 共存，层级合成有额外开销
游戏生态游戏圈、游戏中心入口、微信游戏报、玩一玩基本没有
包体上限主包 4MB / 总包 20MB（分包）主包 2MB / 总包 30MB
开发成本需适配小游戏 API（wx.* 与小程序基本一致）可复用小程序组件库
适用场景纯游戏产品游戏只是 App 的一个子功能
结论：选微信小游戏 本项目的唯一功能就是游戏，不存在「页面 + 游戏」混合需求；而小游戏的游戏圈 + 游戏中心分发是休闲品类留存的关键。 本项目不使用任何 DOM 组件（结算浮层也直接画在 Canvas 上，见原型实现），因此迁移到小程序形态的成本极低。 若需求方坚持小程序形态：把 game.js 主循环搬到页面内的 canvas type="2d"， UI 层（选关页 / 设置页）改用 WXML 组件即可，核心逻辑层 core/* 与渲染层可 100% 复用。

13.5 性能要点

问题做法收益
每帧 createLinearGradient原型里每个方块都建渐变，正式版必须改为预渲染到离屏 Canvas（6 色 × 3 类 = 18 张小图），绘制时 drawImage方块绘制开销降约 8 倍
shadowBlur 滥用仅用于小球（≤16 次/帧）与分裂块；分裂块可改为预渲染带光晕的图shadowBlur 是 Canvas 最贵操作，安卓上尤甚
粒子数量总粒子上限 200，超限丢弃最旧；使用对象池复用避免 GC 抖动
静态层缓存背景渐变 + 星点 + 容器网格只画一次（仅入场时重画），后续 drawImage 贴回省掉每帧最贵的大面积渐变填充
物理开销已为 O(1)/球：16 球 × 8 子步进 × ≤4 格 = 512 次检测/帧无需空间划分结构
音频实例InnerAudioContext 实例池（高频音效最多 4 个）+ 节流，避免同时创建十几个实例避免呲呲爆音与内存泄漏

性能预算：中端机（骁龙 765G / 天玑 800 等级）稳定 60fps，单帧 CPU 开销小于 6ms； 低端机可降级：关拖尾 → 同屏球上限 16→12 → 粒子上限 200→80 → 锁 30fps。

function collideWorld(b) {
  switchZone(b);                       // catch ⇄ arena
  hitContainerWall(b);                 // 左/右（两区）+ 顶（仅 arena）
  const hit = gridHit(b.x, b.y, b.r);  // 取穿透最深的一个单元
  if (hit) {
    if (isDestructible(hit.cell.type)) { destroy(hit, b); reflect(b, hit.n); }
    else                               { reflect(b, hit.n); spark(b); }

❗ 目标仍未达成：v2 仿真实测 1.9% ~ 3.0%，虽高于 v1（0.2%~1.5%，因 v2 漏接即永久损失 3 颗配额之一、代价变重），但仍低于目标带。 v2 接住回弹已是维持回弹链与连击的核心，但尚未形成“漏接风险”——缓解方向见 §11.7 的第 ① 条，需需求方试玩后拍板
