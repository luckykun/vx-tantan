# 弹弹消消乐 · 设计交付物索引（v2）

面向微信小游戏的休闲弹射消除项目。本仓库当前处于 **M0（玩法原型）v2 已完成** 阶段，
交付物为：一份完整游戏设计稿、一套高保真界面视觉稿、一个可直接试玩的 Canvas 物理原型，
以及一个用作关卡平衡回归门禁的无头仿真脚本。

**v1 → v2 的 4 项变更已落实**（详见 [`specs/design-v2-changes.md`](specs/design-v2-changes.md)）：
① 9 列 → **30 列**网格（方块 26/37/49 → 101/167/212）；② 挡板「接住=转弹药」→ **接住后按拖动方向回弹**；
④ 星级「按剩余发射比例」→ **按耗时**；⑤ 删方向虚线，只留**弹道预测点列**。

**尚未开始**小游戏工程代码（`js/` 业务目录、`game.json` 等均不存在），M1 及以后见设计稿 §14 排期。

## 四、关键实测数据摘要（v2）

以下数字来自 `balance-sim.js` 无头仿真（复用原型纯逻辑层，非估算）。
**v2 为 3 球模型 + 接住回弹 + 耗时评星**，与 v1 的 9 列回合制不可横向对比。

| 关卡 | 球 / 方块 | 新手通关率 | 熟练通关率 | 胜局均耗时 | starTimes [3★, 2★] |
|---|---|---|---|---|---|
| 1 初识弹球 | 3 / 101 | 80% | 83% | 54~59s | [55, 90] |
| 2 缺口偏置 | 3 / 167 | 68~76% | 85~90% | 90~94s | [70, 120] |
| 3 满屏窄口 | 3 / 212 | 60~65% | 75~78% | 107~123s | [100, 165] |

> **口径说明**：新手 / 熟练两档均取 5 个种子的均值区间；上表与 `specs/design-v2-changes.md` 六、配平实测终值 一致。
> 单种子门禁（`balance-sim.js 250 250 20261020`）产出新手 80/78/60%、熟练 75/85/76%；两口径差异均来自抽样噪声。

**v2 门禁口径**（与 v1 不同，已从双区间改为单地板）：
- 新手 floor：L1 ≥ 60% / L2 ≥ 50% / L3 ≥ 45%；
- 熟练只看全局兜底 ≥ 40%，**不设无聊上限**（HARD.max=1.0）： 3 球锁死难度下满通关合法。

物理健壮性：1500 局 **0 卡死 / 0 穿透**；同屏峰值 4.3 颗（上限 16）。

**三项必须知道的 v2 实测结论**（详见 §11.4 与 §15.2）：

1. **漏接率 1.9% ~ 3.0%**（v1 仅 0.2~1.5%） —— 挡板变窄到 64px + 无重力接住回弹角度不可预测共同作用，接住回弹自身供给了适中的失败风险，无需额外惩罚机制。
2. **开底频率已回落到兜底区间 0.15~0.40 次/局**（v1 为 0.27~0.78） —— v2 3 球 54~123s 内清屏，22s 停滞只在真残局触发，240s 硬超时兼作双保险。
3. **v1 的“连射原点污染”在 v2 自然消解** —— v2 删除 spawnQueue / heldBalls，无下次弹药原点概念；埋点 `shotOriginDrift` → `lose_cause`。

## 六、复现与校验

改关卡数据或物理参数后**必须重跑门禁**，两步都需退出码 0：

```powershell
# ① 单种子门禁（每关每档 250 局，含物理健壮性压测）
#    退出码 0 = 通关率全部落在区间内且无卡死 / 无穿透
node design/balance-sim.js 250 250 20261020

# ② 跨种子复核（默认 5 个种子 × 每档 150 局 = 30 组，逐组独立判定，不允许用均值掩盖）
#    退出码 0 = 通关率不依赖种子选择。§11.3 的全部数字由它产出
#    ⚠ v2 建议 ≥ 50 局/档：N=20 时 L3・新手 seed 424242 会噪到 40% 越出 floor 45%；N=50 时最差 48% 仍高过下限 3pp
node design/seed-check.js
node design/seed-check.js 50                      # v2 实测采用的口径
node design/seed-check.js 250                    # 提高每档局数，极差会显著收窄
node design/seed-check.js 150 20261020,424242,7  # 只跑指定种子

# ③ 素材校验（看板模式：列已投放 / 待投放；不合规才非 0）
node src/js/assets-check.js
node src/js/assets-check.js --strict   # 素材补齐后改用此命令作门禁
node src/js/assets-check.js --init     # 按清单创建 src/assets/ 空目录骨架
```

两个脚本的关系：`balance-sim.js` 回答「这个配置达标了吗」，`seed-check.js` 回答「达标是不是运气」。
**只跑前者就宣布配平完成是不可靠的**，因为单种子带 ±3~9pp 抽样噪声。`assets-check.js` 与它们同一约定：退出码 0 即通过。

素材层当前为**代码就绪、44 项素材文件待投放**状态。两者不冲突不是侥幸：加载层对每项素材都定了回退路径
（位图缺则 Canvas 程序绘制，音效缺则 WebAudio 振荡器合成，频率时长与设计稿 §12 一致），
所以投放前后原型行为一致、可玩性不变，补上文件即自动升级画质与听感，**不需改一行代码**。具体清单见 [`src/assets/README.md`](src/assets/README.md)。

三条必须遵守的约束（违反任一条，门禁结果都不可信，原因见 §11.1）：

1. **必须固定随机种子**，否则 ±3~9pp 的抽样抖动会让门禁时过时不过。
2. **每关每档不少于 250 局**，低于此值极差会大到无法作为结论。
3. **玩家模型必须带人类约束**（REACT 反应粒度 + ERR 落点误差），
   否则它是一个完美接球机器，漏接率恒为 0、难度被系统性低估。

改关卡定位时应改 `balance-sim.js` 里的 `BANDS`，**而不是改断言阈值去将就测出来的数字**。
v2 BANDS 已从 v1 的双区间改为**单地板**：新手 floor L1/L2/L3 = 60/50/45%，熟练只保留全局兜底 ≥ 40%，`HARD.max = 1.0`（3 球锁死难度下满通关不判为“无聊”）。
